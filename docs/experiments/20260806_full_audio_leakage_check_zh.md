# Full-audio 泄漏检查：对"全音频 88%"的受控复现（2026-08-06）

**状态：** 已完成，结论明确；**数据：** 同锁定基准快照 + 完整音频

## 问题

项目负责人报告全音频准确率 88%，远高于 0.5 s 接触窗的 73%。我们的锁定证据（严格 Pre 随机、瞬态移除塌到 0.50）与该数字冲突。本实验在防泄漏协议下复现负责人的条件，定位高分来源。

## 结果

用 BEATs 编码器、同一来源分组协议：

| 输入音频 | Event BA | AUC |
|---|---:|---:|
| **完整音频（不切窗）** | **0.777** | **0.875** |
| 击球后 4000 ms | 0.705 | 0.793 |
| 击球后 1000 ms | 0.694 | 0.758 |
| 击球前 1000 ms | 0.570 | 0.595 |
| 200 ms 事件窗 | 0.606 | 0.629 |
| 严格 Pre 窗 | ≈0.51（随机） | — |

## 结论

- 全音频确实能到 0.777，**但增益几乎全部来自击球之后的内容**（跑者、观众、解说——它们直接编码了击球结果），而不是击球声本身：
  - 只给击球后片段就能到 0.69–0.71；
  - 只给击球前片段只有 0.57；
  - 掐掉瞬态只剩上下文时负控仍干净。
- **部署时无法获得"知道结果的后文"**，因此全音频/长窗口高分属于结果泄漏，不能作为模型能力的证据。
- 对队友的含义：**不要用全长音频报结果；对比实验一律用峰值居中短窗 + 严格 Pre 负控。**
